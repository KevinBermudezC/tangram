## ADDED Requirements

### Requirement: POST /generate produces a Diagram

The backend SHALL expose `POST /generate` accepting a JSON body `{ "prompt": str }` and returning, on success, a full `Diagram` JSON document conforming to `app/schemas/diagram.py`.

#### Scenario: Happy path returns a valid Diagram

- **WHEN** a client POSTs `{"prompt": "I want to build a delivery app"}` to `/generate`
- **THEN** the response is 200 with a body that validates against the `Diagram` Pydantic model
- **AND** every node has a non-empty `id`, a known `type`, and a `position` with numeric x and y
- **AND** every edge references node ids that exist in `nodes`

### Requirement: LLM produces only the content; the backend owns id, timestamps, positions

The generator service SHALL ask the LLM for a `GeneratedDiagramContent` (nodes, edges, name, description). The full `Diagram` SHALL be assembled server-side with a backend-generated id (ULID), server-time `createdAt`/`updatedAt`, and positions assigned by `auto_layout`.

#### Scenario: LLM never decides ids or timestamps

- **WHEN** a request is processed
- **THEN** the structured-output schema sent to the LLM is `GeneratedDiagramContent`, not `Diagram`
- **AND** the returned diagram's `id` is generated by the backend
- **AND** the returned diagram's `metadata.createdAt` and `updatedAt` are server-side timestamps

### Requirement: Auto-layout assigns deterministic positions

The `auto_layout` function SHALL assign a `Position` to every node based on a column-by-type layout. Same input nodes SHALL yield the same positions across calls.

#### Scenario: Frontend nodes appear on the left

- **WHEN** auto_layout is called on a node of type `frontend`
- **THEN** the assigned x coordinate is the leftmost column

#### Scenario: Database nodes appear on the right

- **WHEN** auto_layout is called on a node of type `database`
- **THEN** the assigned x coordinate is the rightmost column

#### Scenario: Deterministic across calls

- **WHEN** auto_layout is called twice with identical inputs
- **THEN** the two outputs are equal

#### Scenario: Multiple nodes of the same type stack vertically

- **WHEN** auto_layout is called on three nodes of type `backend`
- **THEN** they share an x coordinate and have distinct y coordinates with a consistent gap

### Requirement: Input validation before LLM call

The endpoint SHALL reject requests whose `prompt` exceeds `MAX_INPUT_CHARS` or is empty, before any LLM call is made.

#### Scenario: Empty prompt is rejected with 422

- **WHEN** a client POSTs `{"prompt": ""}`
- **THEN** the response status is 422
- **AND** no LLM call is made

#### Scenario: Oversized prompt is rejected with 413

- **WHEN** a client POSTs a `prompt` longer than `MAX_INPUT_CHARS`
- **THEN** the response status is 413
- **AND** no LLM call is made

### Requirement: HTTP error mapping for LLM failures

The endpoint SHALL map `LLMError` subclasses to HTTP responses. Each response body SHALL include a stable `code` field so callers can branch programmatically.

#### Scenario: LLMConfigError → 503

- **WHEN** the LLM provider is misconfigured (e.g. missing API key)
- **THEN** the endpoint returns 503 with `code` set to `llm_config_error`

#### Scenario: LLMTimeoutError → 504

- **WHEN** the LLM call times out
- **THEN** the endpoint returns 504 with `code` set to `llm_timeout`

#### Scenario: LLMRateLimited → 429

- **WHEN** the LLM provider rate-limits the call
- **THEN** the endpoint returns 429 with `code` set to `llm_rate_limited`

#### Scenario: LLMInvalidResponse → 502

- **WHEN** the LLM returns content that fails validation after a retry
- **THEN** the endpoint returns 502 with `code` set to `llm_invalid_response`

### Requirement: Edge integrity validated server-side

Before returning, the generator SHALL verify that every edge's `source` and `target` references a node id present in the same diagram. Inconsistent diagrams SHALL surface as `LLMInvalidResponse` → 502.

#### Scenario: Edge with unknown source fails

- **WHEN** the LLM returns a diagram whose edge references a node id not in `nodes`
- **THEN** the endpoint returns 502 with `code` set to `llm_invalid_response`

### Requirement: Independent IDs across calls

Repeated identical requests SHALL produce different diagram `id` values. The endpoint is non-idempotent by design.

#### Scenario: Two identical requests produce different ids

- **WHEN** two requests with the same prompt body are made
- **THEN** the returned diagrams have different `id` values
